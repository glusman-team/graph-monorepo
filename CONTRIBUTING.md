# Contributing to graph-monorepo

Start with the [documentation homepage](https://glusman-team.github.io/graph-monorepo/) and [architecture guide](https://glusman-team.github.io/graph-monorepo/architecture/). This repository contains independent Dagster projects, a dynamic Phoenix reader, and static documentation.

## Setup

Use Nix with flakes and optionally direnv. The default development shell supplies uv, Node, Go, Elixir/OTP, Nx, linters, security scanners, hooks, and interactive agent tooling. Use `nix develop .#deploy` for the CI/production toolchain without Agent of Empires.

```sh
git clone https://github.com/glusman-team/graph-monorepo.git
cd graph-monorepo
direnv allow             # or nix develop
npm ci
make hooks
```

Run heavy Linkouts tests/builds on `wenceslaus` with at most four CPUs. Use `/users/sgoetz/Code/linkouts-port-test` for isolated port verification; do not disturb the dirty DAKP checkout at `/users/sgoetz/Code/graph-monorepo`. Local editing, synchronization, and `gofmt` are fine.

The committed `.envrc` contains only `use flake`; `.envrc.example` shows public settings. Keep credentials outside Git. A copied `~/.envrc` must not be edited or printed during verification.

## Component ownership

| Path | Responsibility |
| --- | --- |
| `dagster/projects/dakp/` | DAKP KGX production. |
| `dagster/projects/linkouts/` | Linkouts contracts, Dagster assets/jobs, and hidden Go worker. |
| `sites/linkouts/` | Dynamic Phoenix pages, `kgs/*.exs`, dictionaries, and Fly packaging. |
| `sites/docs/` | Starlight content, navigation, search, and Pages output. |
| `dagster/libs/` | Generic shared Python only. |

Do not import implementation across Dagster projects. Pipeline packages never import Dagster. `mo-dagster` is the shared library allowed to import it. Go modules are independent; do not add a root `go.work`.

KG-building DAGs publish KGX NDJSON only. Linkouts consumes KGX and materializes a compressed serving index, not a KG output format.

## Daily loop

```sh
scripts/run-nx-affected.sh
make lint
make test
make go-test-race
make docs-test
make locks
prek run --all-files --hook-stage pre-commit
prek run --all-files --hook-stage pre-push
```

`make help` lists component commands, including `dakp-test`, `linkouts-test`, `linkouts-contract-test`, `linkouts-web-build`, `linkouts-dialyzer`, and `linkouts-check-deploy`.

`make check` is the offline aggregate after dependencies are available. Network-facing vulnerability audits are separate CI gates. Live DailyMed checks are opt-in, not offline tests.

## Artifact and workflow rules

- Stages hand off through published artifact references under `$MO_PUBLISHED_ROOT`, with lineage-only `deps`, not Dagster value inputs.
- Every output has a narrow manual job and tests proving it can run without rebuilding upstream stages.
- A missing or modified reference fails; it is not silently regenerated by a consumer.
- Linkouts uses typed launch configuration for non-secret run-specific fields and process environment for paths/credentials.
- `linkouts_upload` is manual and contains only stage, publish, status, and probe. Do not add schedules or sensors without an approved design.
- Provisioning is a separate manual job. Destructive definitions require an explicit code-location environment flag and execution confirmation.
- Never put secrets in Pipes extras, run configuration, metadata, or logs.
- Tests use fake engines and disposable file stores. No test may mutate a real Cosmos account, Fly app, or public dataset.

## Contract changes

`dagster/projects/linkouts/contracts/` is the single canonical stored-document corpus. `fixtures/kgx/` is the small writer input corpus. Go regenerates committed bytes; Phoenix reads those exact bytes. Do not copy fixtures into language-specific directories or update goldens merely to hide a regression.

```sh
make linkouts-contract-test
```

An intentional format change must update both languages, review the byte diff, and pass dictionary and legacy-field tests. Whitespace hooks exclude fixture/golden directories because their bytes are part of the contract.

## Quality gates

Pre-commit runs whitespace/metadata checks, secret scanning, Ruff, module-aware Go formatting, project-aware Mix formatting, Prettier, and Nix formatting. Pre-push adds recursive locks, both Go race suites, affected Nx tests/lint, Dialyzer, Actionlint, ShellCheck, deployment checks, and flake evaluation.

CI uses tested path detection and shared-contract fan-out. Writer changes exercise the reader and integration; reader changes exercise the writer goldens. `CI Required` is the aggregate branch-protection status. Go, Hex, and npm vulnerability scans are blocking; do not add permanent `continue-on-error`.

Formatting: Ruff line length 100, `golangci-lint fmt`, `mix format`, strict Credo, Prettier, and nixfmt-tree. User-facing text is ASCII. Use conventional commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).

The npm overrides for Nx's `minimatch` and `undici` are security fixes. Remove them only after upstream dependencies resolve to patched versions and clean `npm audit`, Nx tests, and cache checks pass.

## Adding components

- **New KG/DAG:** follow `.pi/skills/add-dag/SKILL.md`; add the code location, Dagster-free package, independent worker module, narrow jobs, Nx targets, workspace registration, scoped CI, and tests.
- **New Go worker:** follow `.pi/skills/add-worker-go/SKILL.md`; commands belong under `cmd/`, reusable operations under `internal/`, and Pipes payloads stay typed and secret-free.
- **New Linkouts display:** follow `.pi/skills/linkouts-display/SKILL.md`; inspect real KGX, review a declarative starter, add aliases for field drift, and run compiled validation.
- **Linkouts operating work:** follow `.pi/skills/linkouts-operations/SKILL.md` and the Starlight runbooks. Request explicit authorization before any real mutation.

## Pull requests and reporting

Include exact commands/results, regression tests, contract impact, and any removed code or dependencies. Never weaken assertions, inflate timeouts, or skip an applicable gate to get green.

Use repository issue templates for bugs, features, or KG display requests. Security reports go through [private vulnerability reporting](https://github.com/glusman-team/graph-monorepo/security), not public issues. Contributors follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
