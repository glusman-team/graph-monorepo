DAKP: Drug Approvals Knowledge Provider

A KGX knowledge graph of FDA and EMA approved drug-disease treatment relationships, observed applied-to-treat uses from FAERS and Health Canada's Canada Vigilance database, and contraindications text-mined from DailyMed Structured Product Labels. Built with Tablassert, validated against the Biolink Model. Live dataset: SkyeAv/drug-approvals-kp.

Latest release

1.25.1 - 16,427 nodes, 136,317 edges, 0 validation failures, biolink-model 4.4.6. Every release publishes an NDJSON node/edge pair plus a Resource Ingest Guide (RIG); older releases stay downloadable through dataset tags (v<version>) even though main carries only the latest.

Poison screen (new in 1.25.1)

The ICD-10-CM Table of Drugs and Chemicals marks each substance with poisoning and adverse-effect codes. A substance whose Adverse-effect column is empty has no use under proper administration (Official Guidelines I.C.19.e), so it must never carry an applied-to-treat claim. The screen removes such substances two ways, and every biolink:applied_to_treat edge cites infores:icd10cm as a supporting data source:

  • Wording: observed-use rows whose subject text names a screened substance (T36-T65 ranges) are dropped at load by a single Tablassert anti-join filter.
  • Identifier: subject resolution excludes 350 identifiers whose own name is a screened substance, so a reporter spelling that resolves to a poison (FAERS "LEVOXINE" resolves to hydrazine) or a label ingredient (turpentine) cannot surface as a node in any predicate.

Substances that regulator label text names as medicines are exempt (lithium, zinc, arsenic trioxide, permethrin). Water-as-substance identifiers and wordings are excluded separately. GHB/GBL (sodium oxybate, an approved narcolepsy medicine) are deliberately not screened. Full scope and rationale live in each release's RIG.

Loading the data

BASE=https://huggingface.co/datasets/SkyeAv/drug-approvals-kp/resolve/main/1.25.1
curl -LO $BASE/DRUG_APPROVALS_KP_1.25.1.edges.ndjson
curl -LO $BASE/DRUG_APPROVALS_KP_1.25.1.nodes.ndjson

# or as a dataset
from datasets import load_dataset
edges = load_dataset("SkyeAv/drug-approvals-kp", "1.25.1_edges")

Every edge carries provenance (sources rooted at infores:drugapprovals-kp), evidence fields where applicable (number_of_cases, regulatory_approvals, publications, context qualifiers), and a species_context_qualifier naming the organism (NCBITaxon:9606 on human edges, veterinary taxa on animal-drug approvals).

Running the pipeline

# one output only (inside dagster/projects/dakp)
uv run dagster job execute -j dakp_build_kg_build -m dakp_dag.definitions

# the whole DAG through the UI
make dev    # Dagster UI on http://localhost:3000, launch dakp_build

Stage-to-stage handoff is the published artifact under $MO_PUBLISHED_ROOT, never a Dagster value input, so any single stage can build alone. See the repo README for the full command set.
